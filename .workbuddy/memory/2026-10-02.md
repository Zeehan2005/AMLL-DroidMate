
## 修复：版本号规则变化导致 getCurrentVersionName() 取不到有效版本号
- 现象：设置页「当前版本: 」空白，更新检查恒提示「发现新版本」。
- 根因链条：
  1. 版本号规则已改为 SemVer（`customVersion` 直供 `versionName`，如 `v4.3.1-alpha.1`），而 `customVersion` 当前为空串 → manifest 的 `versionName` 为空。
  2. 旧 `getCurrentVersionName()` 写的是 `packageInfo.versionName ?: "unknown"`——AGP 写入空串时 `versionName` 返回的是 "" 而非 null，**Elvis 拦不住空串**，于是返回空值，`parseStable("")` 亦为 null → `installed.stable == null` → `isRemoteNewer` 恒返回 true。
  3. 旧 `Alpha <时间戳>` 规则已被 9/21 那次改造移除，不再被识别为 Alpha，属于预期（远程 tag 侧）；问题出在「本地 versionName 为空」这一层。
- 修复：
  - `app/build.gradle.kts`：新增 `resolveVersionName()`，`customVersion` 留空时自动生成开发版 `v0.0.0-alpha<时间戳>`（符合新规则的 alphaRegex）；`versionName` 与 APK 文件名统一改用它，保证永不为空白。
  - 新增 `global/AppVersion.kt`（统一取值入口）：API 33+ 走 `PackageManager.PackageInfoFlags.of(0)`（旧分支保留 deprecated 重载），先 trim 再判空，空/异常一律回落 `"unknown"`。
  - `GitHubUpdateChecker.getCurrentVersionName`、`SettingsActivity.kt`(原私有同名函数已删除) 均改为调用 `AppVersion.current(context)`，消掉两份重复实现。
- 验证：`java -jar gradle/wrapper/gradle-wrapper.jar :app:compileDebugKotlin --offline` BUILD SUCCESSFUL；`:app:processDebugMainManifest` 后合并 manifest 为 `android:versionName="v0.0.0-alpha<时间戳>"`（可被 stableRegex/alphaRegex 正确解析为 ALPHA 渠道、0.0.0）。
