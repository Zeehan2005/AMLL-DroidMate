## MainScreen.kt：歌词空态占位底图
- 需求：出现「选择歌词来显示」时，若无专辑图则使用 `drawable-anydpi/background_blue_black_light_1591226.png` 作为占位底图，避免整块纯黑。
- `LyricsEmptyState()` 改为接收 `nowPlaying: NowPlayingMusic?`；`useFallbackArt = nowPlaying == null || albumArtUri.isNullOrBlank()`（与 `LyricsVisualLayer` 的 effectiveAlbumArtUri 判断对齐），命中时用 `Image(painterResource(...))` + `ContentScale.Crop` 铺满 + `Color.Black(0.55f)` 压暗后叠文字。
- 三处调用点（横屏全屏 411、横屏右侧歌词卡 726、竖屏歌词卡 775）统一传 `nowPlaying`。
- 新增 import：`androidx.compose.foundation.Image`、`androidx.compose.ui.res.painterResource`。
- NB：此处用 `painterResource(R.drawable.xxx)` 而非 `LyricsVisualLayer` 里的 `android.resource://pkg/drawable/xxx` URI（后者供 Coil/AsyncImage 用）。
- 编译验证：`:app:compileDebugKotlin --offline` BUILD SUCCESSFUL。
- **修正（用户反馈方案不对，已改）**：不要在无专辑图时用 `painterResource` 直接铺 Compose `Image`——会盖住 WebView 渲染的背景。正确做法是让**背景渲染组件**渲染这张占位图：`LyricsVisualLayer.effectiveAlbumArtUri` 改为 `nowPlaying?.albumArtUri?.takeIf { it.isNotBlank() } ?: fallbackAlbumArtUri`，即 nowPlaying==null 时也回落占位图，这样原生模糊背景(AsyncImage) 与 AMLL WebView 背景渲染器(`window.updateAlbumArt`) 都能拿到图。`if (useAndroidBlur && effectiveAlbumArtUri != null)` 简化为 `if (useAndroidBlur)`（此前编译报 always-true 警告）。
- `LyricsEmptyState(nowPlaying)` 只保留 `Color.Black(0.35f)` 压暗蒙版（占位图偏亮，白字需保对比度），不再自己画底图；三处调用点仍传 `nowPlaying`。
- 链路备忘：`android.resource://<pkg>/drawable/<name>` → `AMLLLyricsView.convertFileUriToDataUrl` 已支持该 scheme（走 ContentResolver）；`getMimeType` 靠扩展名判定、该 URI 无扩展名 → 回落 `image/jpeg`（PNG 字节以 image/jpeg 的 data URL 传入，WebView 会嗅探，可用；「有歌曲但无专辑图」场景早已走这条链路）。
