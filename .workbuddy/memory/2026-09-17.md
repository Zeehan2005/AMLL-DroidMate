# 2026-09-17

## 修复：歌词字重/字号调节「未生效」

### 根因
`app/src/main/assets/amll/` 整个目录是 **构建产物**，由 `app/build.gradle.kts` 的 `buildFrontend` 任务生成：
该任务第 121 行 `assetsDir.deleteRecursively()` 先清空 `app/src/main/assets/amll/`，再 `distDir.copyRecursively` + 复制 `frontend/styles.css` 与 `index.html`。
因此**直接改 `app/src/main/assets/amll/styles.css` 是无用的**——每次 `:app:compileDebugKotlin`（依赖 preBuild→buildFrontend）都会被 `frontend/styles.css` 覆盖掉。

上次（9/12）的实现逻辑本身正确，唯一问题是 CSS 规则没真正落地到真源。

### 修复
- 真源改为 **`frontend/styles.css`**（加 `--amll-user-font-size` 字号中转 + `font-weight: var(--amll-lp-font-weight,400)`）。
- 在 `AMLLLyricsView.kt` 的字重/字号注入 JS 中**增加 inline style 兜底**：除写根 CSS 变量外，直接对 `.amll-lyric-player` 元素设 `style.fontWeight` / `style.fontSize`，双保险，不再依赖样式表是否落地。
- 重新跑 `buildFrontend`（随 compileDebugKotlin 触发）后，`app/src/main/assets/amll/styles.css` 已正确包含新规则，Kotlin 编译通过。

### 后续约定（重要）
- 改歌词 WebView 的样式 → 改 `frontend/styles.css`；改前端逻辑 → 改 `frontend/src/`；改 JS 注入桥 → 改 `AMLLLyricsView.kt`（Kotlin 侧，不在 bundle 内）。
- 不要直接编辑 `app/src/main/assets/amll/` 下的任何文件，它会被 `buildFrontend` 覆盖。
- 沙箱内 `./gradlew` 脚本缺 uname/sed 跑不起来，需直跑 `java -jar gradle/wrapper/gradle-wrapper.jar :app:compileDebugKotlin --offline`。
