# 2026-09-05

## Gradle 10 兼容性废弃警告诊断
- 项目：AMLL-DroidMate2（Gradle 9.7.1 wrapper，AGP 9.2.1，Kotlin 2.3.21）。
- 现象：build 报 "Deprecated Gradle features were used... incompatible with Gradle 10"。
- 根因（已用 `--warning-mode all --stacktrace` 定位）：
  1. `Configuration on demand is an incubating feature` → 来自 `gradle.properties` 的 `org.gradle.configureondemand=true`。已从 gradle.properties 删除。
  2. `Using a Project object as a dependency notation has been deprecated`（Gradle 10 会报错）→ 来自 AGP 9.2.1 内部 `com.android.build.gradle.internal.dependency.VariantDependenciesBuilder.build`（构建 test variant 依赖图时）。属插件内部代码，**无法通过修改 build 脚本修复**。
- 已修复：删除 `org.gradle.configureondemand=true` 与 `kotlin.incremental.js=true`（后者无 Kotlin/JS，已废弃）。
- 残留废弃项处置建议：升级到最新 AGP 9.x（Google 官方建议升级 AGP 9.x 以清除 Gradle 10 废弃警告）；或暂时忽略（Gradle 9.7.1 下构建正常，仅升级到 Gradle 10 时才报错）。注意 AGP 升级需同步对齐 Gradle/Kotlin/SDK 版本。
- 另注意：`app/build.gradle.kts` 设 `JavaVersion.VERSION_25`，但本机仅 JDK 21，实际编译可能失败（需 JDK 25 toolchain 或 Android Studio 自带 JDK）。

## frontend Vite 8 配置告警修复
- 现象：`vite build` 报两类告警：① `configLoader: 'native'` 不支持 CJS 中的 ESM 语法；② `inlineDynamicImports` 已废弃。
- 根因：`frontend/package.json` 为 `"type": "commonjs"`，但 `vite.config.js` 用了 ESM（`import`/`export`）与 `__dirname`；Vite 8 native loader 把 `.js` 当 CJS 解析。
- 修复（已验证 `vite build` 无告警）：
  1. `git mv vite.config.js vite.config.mjs`（ESM 后缀，与 package.json 的 commonjs 解耦）。
  2. `rollupOptions.output.inlineDynamicImports: true` → `codeSplitting: false`。
  3. `resolve(__dirname, ...)` → `resolve(import.meta.dirname, ...)`（ESM 无 `__dirname`，Node 20.11+ 支持 `import.meta.dirname`，本机 Node 22 可用）。
- 注意：`.mjs` 方案无需改 package.json 的 `type`，避免影响其它 CJS 脚本；若日后把 package.json 改为 `type: module`，可改回 `.js`。
